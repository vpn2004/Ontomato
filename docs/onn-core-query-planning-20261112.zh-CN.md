## 问题和实现

此前真实问数中，模型依据通用 DSL 规则生成了行级 DISTINCT 和多步骤查询，原 ONN adapter 拒绝后再由模型调整。跨关系问题约 125 秒包含推理、工具调用、失败重试和答案生成，不等于 ONN 数据库查询时间。

本轮在 Ontomato 侧完成以下修改：

1. `DataAdapter` 增加默认返回空内容的规划规则及示例方法。ONN 实现说明当前执行约束；其他 adapter 继承默认行为。ABC 的 `getDslSyntax`、`getDslExample` 按当前 domain 的数据源附加规则；ONN 用可执行的单步 count-distinct 示例替换含不支持表达式的通用示例。旧 DSL Cooker 生成入口也附加约束。
2. 标量和关系查询的公共残余求值器支持行级 DISTINCT：任一非聚合输出字段声明 `distinct:true` 时，对整个输出元组去重。数值规范化、日期按时间点比较，字符串不与数字合并；空值参与去重。去重在 offset/count 前完成。排序只允许引用投影字段；行级去重混合聚合明确拒绝，要求拆为临时步骤。
3. 新增 `OnnCoreQueryPlan`，支持同一 DSL 内的 2–4 步线性执行。第一步读取单类或既有受支持的关系图；后续每步只读取紧邻上一步的 `save_table`，可以筛选、投影、去重、分组、HAVING、聚合、排序和最终分页。复用既有类型和计算规则，不引入任意代码执行或物理临时表。
4. 全部步骤在首个业务数据读取前编译校验。只接受中间 `to_user:false`、唯一临时表名、最终 `to_user:true`；拒绝分支、临时表关联、表达式、后续直接访问业务类、业务类重名临时表和额外协议字段。schema/capabilities 读取不属于这一“业务读取前”保证。
5. 中间结果强制物化，禁用 binding window 提前分页；不会默认只取 100 行。通过 5000 行哨兵上限将可接受中间结果限定为最多 4999 行，达到哨兵时拒绝产生答案。明确拒绝用户提供的中间 limit，避免基于部分数据计算总数。最终省略 limit 仍沿用既有 100 行默认值。
6. 临时表字段别名映射到内部列，包括名为 `id` 的别名，防止与内部行身份混淆。类型贯穿步骤，所有临时结果仅在请求对象中存在。执行仍经过原有向量拆分和行权限注入入口，不赋予任何写入能力。
7. 多步骤结果保留首次数据读取的来源、版本、一致性、释放和工作量证据，新增 `localPipelineSteps`、`intermediateRows`、`pipelineEvaluation`、`localPipelineMs`；已有 `timingMs.total` 包含本地后续步骤。不把它称为数据库聚合下推。
8. 不支持的查询形态附带可操作的约束说明。此类拒绝不再清空 metadata cache，避免模型改写过程中无意义地反复加载 schema；其他异常继续沿用既有失效处理。

这轮实现采用有上限的本地临时结果求值，没有把任意多步骤转化为 ONN 原生查询，也没有增加跨请求查询结果缓存。单步支持的计数等仍按原有规则下推。

## 验证

采用 Maven wrapper，JDK 25 编译目标 release 21；测试显式筛选，未运行数据库、模型或外部系统测试全集：

- data-engine-core：25 项通过，覆盖规划工具的当前 domain/adapter 选择、ONN 示例替换与默认来源隔离、原有 Python 部分结果语义、证据身份、语法和向量入口。
- ONN adapter：151 项通过，涵盖新增规划链、整行去重、HTTP adapter 入口、原有 schema/metadata、snapshot、窗口、聚合下推、计量和条件写协议。均为本地 fixture/loopback，条件写测试没有向 108 写入。
- 新增边界包含：123 行中间结果不会截成默认 100 行；4999/5000 哨兵边界；四步链；错误后续步骤在业务读取前失败；重复路径去重；空值；数值精度与类型区分；日期跨时区等价；临时 `id` 别名；分组/HAVING/排序/分页；空输入；当前请求重用求值器时不保留上轮数据。
- 通过真实 `HttpRequestUtil.executeDsl` 入口验证：先注入行权限，再经 ONN adapter 执行临时聚合，结果只计入满足权限条件的行。
