## Node 版本与影响范围

上一轮仅检查默认 shell，遗漏了已安装的 Node 24。108 实际存在以下独立环境：

| 环境 | 版本 | 已确认的使用者 |
|---|---|---|
| `/usr/bin/node` | 18.20.8 | 游戏广告、演示导航、AI 政务、智能人力四个服务 |
| NVM Node 20，默认 alias 为 `20` | 20.19.3 | Form Guard 使用明确的 v20 可执行文件路径；交互 shell 默认版本也是 20 |
| NVM Node 24 | 24.15.0 | Palantir 学习环境使用明确的 v24 可执行文件路径 |
| 两套 Ontomato Workbench 容器 | 24.18.0 | 各自镜像内部的 Node，独立于宿主机 |

本轮没有升级系统 Node，也没有更改 NVM 默认 alias、服务启动路径或全局软件包。需要 Node 24 的宿主机构建可以使用 `/root/.nvm/versions/node/v24.15.0/bin/node`，并在该构建进程的 PATH 中优先放置对应 bin 目录。Java 引擎部署本身无需升级宿主机 Node。

不建议直接替换 `/usr/bin/node`：这会影响依赖该路径的服务在下次启动时使用的运行时，应逐服务验证依赖、原生模块和启动行为。更改 NVM 默认版本通常不会重启正在运行的进程，但可能影响后续交互命令、使用默认 PATH 的脚本和任务；不能据此宣称全局升级无影响。
