# 问数准备与质检优化计划

目标：减少重复模型往返，同时保留复杂问题所需的查询步骤、执行时间、权限和完整性验证。只改 Ontomato，不修改 ONN Core。

1. TDD：覆盖连续多步骤成功、修改失败查询后恢复、同一失败查询防空转、跨会话隔离。
2. 按需合并查询准备：一次工具调用取得指定对象的字段、直接关系、DSL 语法及适配器示例。保留原有探索工具，允许补充类和关系，不限制任务轮次。
3. 独立质检模型：增加可选 `qualityCheck` 模型引用，未配置时沿用 `query`。参数仍归命名模型所有；规划与代码模型不受影响。旧客户端保存配置不能清除新增绑定。
4. 用完整程序与反例对比现有质检模式和候选快速模式。检查漏过滤、错误去重、关系方向、日期、空值、单位及复杂程序；质量未通过则不启用快速模式。
5. 隔离 E2E：从现有 108 镜像启动候选，验证质量追溯的简单、跨关系、多结果和复杂计算题，检查独立真值、CSV、历史、刷新、取消与质检。
6. 通过验收后备份并部署两套 Ontomato，验证物流回归。记录首表、答案、质检及整轮耗时；不以缩短步骤上限、缩短超时、隐藏失败或返回旧结果实现提速。

已有 adapter 单次 DSL 的能力边界仍存在（例如线性步骤和中间行数上限）。超过单次能力时允许多次查询与受测 Python 计算；不能把它宣传成所有复杂问题无限制支持。
