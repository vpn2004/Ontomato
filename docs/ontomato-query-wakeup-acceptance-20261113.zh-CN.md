## 实现与 TDD 证据

- 引擎使用按会话的消息通知及模型完成信号唤醒查询循环，空闲等待上限为 1 秒，用于检查取消状态。移除消息服务每个操作额外 10 毫秒休眠，保留消息顺序、末尾排空与会话清理。
- 原实现的真实 Harness 模拟回归耗时 11,074 毫秒，失败于 4 秒门槛；同一测试修复后约 1.6 秒（包含人为的 1.5 秒模型等待）。成功、异常、会话隔离、通知先于等待、清理和中断均有定向测试。
- Workbench 最多并行准备两张结果表，连未发布结果也受此限制；乱序完成仍按输入顺序发布。取消/任一准备失败立即停止等待与后续发布，即使某个模型调用没有及时响应取消。
- 首表就绪即显示，答案模型生成时保持表格可见。模型失败时一次发布完整备用内容，避免重复播放不完整表格片段。原始数据、字段单位/时区/比例处理及 CSV 路径保留。
- E2E 发现“已有表格→停止→刷新”会丢显示：查询事实已保存，但最终回答快照尚未生成。历史读取现在从已保存查询事实恢复取消轮次，并标注已停止；已有最终快照仍优先，读取前仍验证线程权限。没有新增数据表或复制一份业务数据。另补充了取消后继续下一轮对话的历史顺序测试，恢复的回答保持在对应问题之后。
- 新增埋点：模型结束至结果交付、每表准备、结果队列排空、首表发布；浏览器以 DOM 可见性记录首表，并检测后续消失。该测量不是精确的屏幕绘制时间。

Java 定向测试 **21/21**，Workbench 定向测试 **47/47**；类型检查、改动文件 lint、Java 构建与运行包哈希核验通过。先保存失败日志，再修改实现；没有运行未过滤的 Java 外部系统测试集。
