# Core 查询类型语义与精确聚合补充需求

日期：2026-11-06。

## 背景与结论

为 Ontomato 开发 ONN adapter 时，已接入 T30 的计数、投影、return、ETag 和免会话能力，并完成实际联调。本需求描述 Core 需要提供的独立查询能力。

以下为现有契约的语义边界和兼容能力缺口，不将其表述为 T30 已承诺修复但没有修好的缺陷。当前调用方通过保留本地计算保证结果正确；补齐后才能进一步减少传输与应用计算。

## R1：按 schema 类型比较、分组与去重

提供显式、可协商的类型语义模式，并保留旧默认行为以兼容现有调用者。同一模式必须覆盖 where/where_logic、group_by、count_distinct 和排序，不能只改某一个入口。

- string 按原字符串处理：`"01"`、`"1"`、`"1.0"` 是不同值；日期外观文本也保持字符串身份。
- datetime 按绝对时刻处理：等价时区表示应在比较、分组和 DISTINCT 中一致归一。
- int/decimal 的比较与去重不能先转 float64。大于 2^53 的相邻整数必须可区分。
- 布尔、数字、文本不隐式跨类型合并；缺失/null 的规则需独立说明。

验收夹具：两对象的 string 属性分别是 `"01"` 和 `"1"`。按该属性分组应得到两组，各计数 1；COUNT DISTINCT 应为 2。108 T30 实测原生 return 将它们合并为一组计数 2，因此调用方目前保留本地分组。

同一套夹具补充日期外观 string、相同时刻的两种 datetime 表示、`9007199254740992` 与 `9007199254740993`，分别覆盖普通查询、分页、pipeline return，以及重启前后。

## R2：精确数值聚合及可选空集语义

提供明确的精确聚合模式：

- 数值输入的原始十进制表示应能进入精确计算；不要求调用方先把所有业务数字改存字符串。
- SUM 与整数 MIN/MAX 不丢失精度；AVG 允许明确选择精度与舍入方式，例如 DECIMAL128 的 34 位、HALF_EVEN。
- 支持空集/全 null 的 SUM 返回 null；保留当前默认 0 也可以，但必须可显式选择并协商能力。
- COUNT(attribute) 仍只统计非空值；路径重复计数与对象去重计数分别保持 paths/objects 语义。
- 返回数字编码需能被调用方无损解析，并声明 decimal 字符串与普通 string 的区别。

验收：0.1 与 1.1 的 SUM 精确为 1.2；1、2、2 的 AVG 按所选精度舍入；大整数相加不丢位；空集及全 null SUM 为 null；真实 0 的 SUM 为 0。108 T30 实测前一个 SUM 为 `1.2000000000000002`，空集为 0；这是当前协议行为，不应通过放宽对拍误差关闭差异。

## R3：多字段全序与窗口语义

提供多字段 order_by，逐项明确方向及 null 摆位，并能使用稳定的对象身份作最后排序键。适用于普通对象结果和 return 聚合结果。

- 同值、null、跨类同名 ID 的顺序可复现。
- 在完成过滤、聚合、HAVING 和完整排序后应用 offset/limit。
- 分页返回完整、精确的总量/一致性状态；不能为了获取窗口重新求值后续页，也不能用结果截断冒充完整结果。
- 对没有显式排序的分组，说明默认全序以及可否请求组内最小对象身份作稳定键，使调用方能保持既有窗口规则。

这是扩大原生排序/窗口接入的后续能力需求。本轮没有将当前单字段排序接口解释为多字段排序已经完成。

## 联合验收与已有边界

能力清单应逐项声明以上模式，包含新契约版本及准确构建身份。未实现或关闭的能力返回明确错误；403、409、422、unknown、truncated 等不得改成成功空集。

交付同输入的新旧结果、负例、快照/权限/重启验证，再由应用完整链路对拍。百万全量计数预算、大扇出多跳性能等 T30 原有未关闭项仍独立保留，不与本需求混为一次已完成的性能承诺。
