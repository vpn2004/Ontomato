# ONN Core 作为业务数据服务的功能需求

日期：2026-10-25  
接收方：ONN Core 开发团队

## 背景与目标

我们正在开发一个独立的 ONN Core HTTP adapter。目标是让外部应用把 ONN Core 作为业务对象和关系的权威数据服务，同时由外部应用自行保存用户、权限配置、会话、任务和运行记录等平台数据。

本需求描述 ONN Core 服务端需要提供并稳定承诺的能力，不规定外部应用的 adapter 实现方式，也不要求 ONN Core 承担外部应用的平台管理数据。

V12.6 T13 报告称 R1-R6 功能整改已关闭，隔离验收 35/35、closure 测试 22/22、本机等价 E2E 15/15 通过。这里将这些修复视为当前基线，不重复提交为新缺陷。报告同时明确，108 服务器上的真实部署验收仍未完成；因此部署版本及其线上行为还需单独闭环。

## 需求范围

ONN Core 作为外部业务数据服务，应能让受支持的客户端：

- 发现服务版本、API 版本和本次部署启用的能力；
- 在明确身份和授权范围内读取对象、关系和 schema；
- 创建、更新和删除对象及关系，并判断写入是否完整、是否与并发修改冲突；
- 在数据规模增长和读取期间数据变化时，取得可继续分页且完整性可证明的结果；
- 在服务升级、迁移和故障恢复后核对数据，并恢复到已验证的备份。

具体 URL 和字段名由 ONN Core 团队决定。最终接口、数据格式、错误码和兼容规则必须形成公开、带版本的契约，并由自动化验收覆盖。

## 功能要求

### F1. 服务版本与能力发现

提供机器可读的版本和能力接口，至少返回：

- 产品版本、源码 commit、构建时间或构建 ID、API 契约版本；
- 当前实例启用的认证方式、授权能力、schema/object/edge 读写、图查询、分页快照、备份迁移能力；
- 每项能力的稳定标识及必要的兼容版本。

健康检查只表示进程可响应，不能代替版本核验。若能力未启用，相关操作应返回稳定的错误码，不得静默降级到另一视图或只返回部分结果。

**验收：** 部署的二进制可通过接口核验 commit 与 API 版本；能力清单准确反映实际配置。对未启用能力的调用返回可识别错误。

### F2. 外部调用身份与授权契约

提供受支持的服务认证方式，使 adapter 能以明确的调用身份访问 ONN Core。若身份由 API gateway 转发，必须规定：

- gateway 如何认证调用者、清理客户端自带的身份头并注入可信身份；
- 后端如何验证该身份，客户端不能通过任意填写角色头取得更高权限；
- 身份、角色及租户（如支持）如何传递到对象、关系、schema 和查询操作；
- 管理员凭据与普通业务访问凭据的区分、轮换和失效方式。

属性权限、继承权限及角色约束应在点查、列表、图遍历、筛选、排序、聚合和批量操作中一致生效。授权信息无法读取或身份无法验证时，应拒绝请求，不得按公开数据放行。

**验收：** 使用隔离环境中的普通用户、受限角色、管理员、无身份及伪造身份头进行正反向验证。受限属性不能经原始响应、关系遍历或聚合旁路读取；真实部署网关与后端的身份链路有可复核证据。

### F3. 稳定对象与关系读写 API

为外部客户端提供有文档、可长期兼容的对象和关系接口：

- 对象身份至少由结构化的 `class_path + id` 表达；关系身份应结构化包含关系类型、源对象和目标对象。身份不得依赖对冒号等分隔符的猜测拆分。
- 支持按身份读取对象，按类分页读取对象，读取指定对象的出边、入边及关系属性。
- 支持创建、更新、删除对象和关系；明确属性缺失、null、覆盖、删除和类型校验语义。
- 对批量操作说明原子性边界。若不支持整批原子提交，必须逐项返回成功、失败和稳定身份，不能只给一个含糊的整体成功状态。
- 定义对象删除对关联边的处理规则，并提供可核验的删除结果。

如果上述接口已存在，本项要求将现有行为、认证要求、DTO 和兼容性正式纳入 API 契约并通过验收，不要求重复实现同一能力。

**验收：** 用包含冒号、Unicode、相同类内 ID、同端点多条不同关系和关系属性的隔离数据，完整执行对象/关系增删改查。每次修改后重新读取，结果与写入一致；歧义身份、错误类型和不存在对象有明确结果，不能误改其他对象或边。

### F4. 并发控制、幂等与写入结果

业务数据服务需要支持客户端识别并发修改和可安全重试的写操作：

- 写入响应返回稳定对象版本、ETag 或等价的并发校验值；客户端可用前置版本条件更新或删除。
- 版本冲突返回稳定冲突错误，不覆盖后来写入的数据。
- 支持幂等请求标识，或提供等价机制，使客户端在超时后重试不会意外重复创建对象/关系或重复执行非幂等操作。
- 写入响应区分已提交、未提交和结果未知；超时后可通过身份或请求标识核查最终状态。
- 对象与关系的跨资源事务能力若不支持，应明确事务边界以及推荐的补偿/恢复方式。

**验收：** 两个客户端从同一版本并发修改时，只有符合版本条件的写入成功；同一幂等请求重放不会产生重复数据；注入响应丢失后可确定操作状态。

### F5. 完整分页与一致读取

为对象列表、关系列表、邻居列表和图查询提供统一的结果完整性契约：

- 明确当前页数量、总匹配数量、是否有下一页及结果是否完整；未知总量必须标记为未知，不得把当前页数量当作总数。
- 提供确定排序和稳定 cursor。若接口承诺精确分页，应避免仅依赖不稳定顺序的 offset。
- 支持快照标识或等价机制，使跨页读取属于同一数据视图；同时标记 schema 版本。
- 如果一致快照尚不支持，应将能力标为未启用，并返回可识别限制；不能把前后总数相同描述为快照一致。
- 扫描上限、分支限制、超时、取消、部分存储失败和降级都必须体现在响应完整性字段或明确错误中。

**验收：** 使用超过单页和服务默认上限的数据集进行读取。翻页后与固定快照的基准集合完全相同，无重复或遗漏；读取期间并发新增、删除和更新时仍保持快照，或明确返回快照失效。故意触发执行上限时，响应不能标记为完整。

### F6. 图查询及关系绑定结果

如果 ONN Core 声明支持图查询或多步 Pipeline，应提供可供外部 adapter 使用的稳定结果模式：

- 每行可按变量取得同一次匹配中的对象身份、对象属性和关系身份；不能只返回末端对象而丢失源对象绑定。
- 过滤、投影、排序和聚合明确作用于哪个对象变量或关系变量。
- 多分支、嵌套遍历、去重、回环、optional、分页和深度/分支上限语义有明确定义。
- 所有已接受条件必须执行。不能理解的条件返回明确客户端错误；存储或执行失败不得变成成功空集。
- 精确计数只能基于完整输入；如果允许部分结果，必须显式标注并与精确计数区分。

若某个查询模式未实现，应在能力清单中关闭并明确拒绝，不能以成功状态返回语义不完整的答案。

**验收：** 使用包含两跳关系、双分支、同端点多条边、目标变量条件、回环和多页结果的固定数据集，对比逐条读取计算出的基准绑定行、聚合值和身份集合。注入存储读取错误时，请求应失败而不是返回空答案。

### F7. Schema 契约与数据迁移

schema 接口应提供一致的版本和类型语义：

- 全量 schema 响应带稳定 fingerprint/version；相同 schema 产生相同版本，结构变化产生新版本。
- 明确继承、属性覆盖、空类型、扩展类型、关系端点、null/missing 和已弃用字段规则。
- schema 变更须校验受影响的后代定义；不兼容变更在落库前拒绝，或要求明确的迁移流程。
- 数据迁移工具应支持 dry-run、冲突报告、可恢复 checkpoint、重复执行保护、数量/哈希核对和回滚材料。
- checkpoint 应绑定源与目标存储身份及相关数据版本，不能拿到另一实例或已变化的数据上继续执行。

**验收：** schema 变化前后版本可核验；继承冲突不会部分写入。对隔离数据集执行 dry-run、迁移中断、恢复、再次执行和回滚，结果符合预期且可通过数量/哈希复核。

### F8. 备份、恢复与升级运维

提供可操作的业务数据保护流程：

- 说明备份包含的对象、关系、schema、索引、配置和版本信息，以及不包含的外部数据。
- 备份产物含数量和校验信息；恢复前验证完整性和目标兼容性。
- 定义版本升级中的数据格式兼容、迁移失败处理、恢复到上一可运行版本的方法。
- 提供在隔离实例执行并可复现的备份恢复验收步骤。

**验收：** 对包含对象、关系和 schema 的隔离数据集备份后恢复到空目标，数量、身份、属性、关系和校验值一致；损坏备份或不兼容目标在写入前被拒绝。

## 交付与验收状态

请 ONN Core 团队针对 F1-F8 逐项给出：现有 API/版本、已覆盖的自动化测试、未满足项、计划版本及部署验证方法。已有能力以文档化和可复现验收为准；不要求对已由 T13 关闭的问题重复开发。

下一次集成验收应使用与源码 commit 和构建 SHA 一致的候选二进制部署到 108，或指定等价的隔离部署，并完成：

1. 版本与能力核对；
2. 认证网关到后端的真实身份验证；
3. 原 T13 35 条验收和 15 条 E2E 回归；
4. 本需求中适用的分页/快照、授权、写入、并发、迁移与备份恢复验收；
5. 清理合成测试数据并提供运行日志、manifest 和二进制 SHA。

只有本机等价重放或仓内测试通过，不能替代目标部署的版本核验和真实服务验收。
