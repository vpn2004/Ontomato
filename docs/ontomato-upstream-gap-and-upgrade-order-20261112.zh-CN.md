## 值得同步的变化

- Manager：可配置对象视图、版本发布、实例图导航与名称显示；修复关系创建及编辑时关联字段保存。
- Agent：分析过程展示和证据复用改进；普通 Agent 调用选定只读 MetricView、确认 Action、小时级调度及调度身份管理。
- 检索：向量资源 HNSW/topK 检索及批量文本上传，修复召回参数绑定。
- adapter：新增 MongoDB、ClickHouse、ArangoDB，补充构建和运行时依赖。上游 v4.1.1 至 v4.1.4 的 DataAdapter、DataAdapterProvider 基础接口文件未改动，有利于保留 ONN 实现。
- 问数：服务端记录回答完成时间，并将质检等待从显示的回答耗时中排除。

新增数据库适配器不会自动提高 ONN 性能。ONN 身份、图查询、缓存、窗口、下推、受控写入及中文内容仍需我们保留并验证。

## 对当前延迟问题的影响

核验 v4.1.4 后，以下文件与当前工作目录内容一致：

- `ABCHarnessServiceImpl.java`：现有轮询等待逻辑。
- `CheckController.java`：现有质检接口等待逻辑。
- `services/data-query/late-fact.ts`：现有晚到事实等待上限。

上游 `9fc867cb` 的实际行为是在 `pendingLateFacts.settleAll()` 前保存 `answer_completed_at`，并据此计算回答耗时；订阅流仍等待质检收尾。其测试也明确断言质检期间运行保持 running。

因此，显示耗时修正值得吸收，但不是此前约 60 秒质检等待的真实消除。已有事件唤醒、持久化后台质检和减少模型调用的优化方向仍有效，应基于升级后的代码重做集成验证。

## 合并风险

以 v4.1.1 为共同基线，对上游变更与本地当前已跟踪文件变更作交集，得到 30 个共同修改文件。逐文件 `git merge-file -p` 预检：17 个可文本合并，13 个出现冲突。

冲突主要涉及构建装配、向量资源服务、Manager API/组件/语言入口、数据查询协议及测试。完整清单保存在本次审计的 `merge-preview.json`。这只是文本预检，不是完整合并、编译或语义验收；没有冲突的文件也需验证权限、对象身份、完整性标记和结果语义。

还存在 PostgreSQL schema 更新：Agent Actions、调度凭据、MetricView、问答 Agent 排序和回答完成时间字段，以及 Java 端向量索引迁移。升级前应备份管理库，并在副本上验证迁移、旧数据读取和恢复路径。

上游 develop 与 v4.1.4 已分叉：API 核验时 develop 为 `1665650ccdee95fca0c1c4b91482c53e5a0fab62`，相对发布版多 1,001 个提交，缺少发布线 16 个提交。不能把它理解成 v4.1.4 的线性后续补丁；包含新的 Agent runtime、shell UI 与部署结构，暂不作为本次升级目标。
