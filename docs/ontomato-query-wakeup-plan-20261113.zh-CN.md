# 问数链路优化计划与验收门槛

本轮只修改 Ontomato，ONN Core 保持原状。基于当前 v4.1.4 与已验收质检优化继续开发。

## P0：本轮执行

1. TDD：先验证真实 Harness 流程在模型完成后能及时结束、结果与末尾消息完整；补充任务通知隔离、取消和清理测试。
2. 引擎将 10 秒固定等待替换为按会话通知，保留有界取消检测与最终消息排空，不增加数据库轮询。
3. Workbench 对独立结果表最多并行准备两张，按原始顺序发布，第一张完成立即显示；覆盖慢首项、乱序完成、流失败与取消。保留字段模型、单位/比例/时区校验与原始数据下载语义。
4. 埋点区分后端事件接收、单表准备、全部表就绪、首表发布和答案完成。并行耗时不能简单求和。
5. 本地定向测试、类型检查、lint、Java 构建后，在 108 隔离副本执行旧新版交替浏览器 E2E。客户总数 42、指定客户计数 1、跨关系序列号与去重数量 17、CSV、历史、刷新和质检均为验收门槛。
6. 独立验收通过才备份并部署 3011/3010，质量场景至少连续两轮跨关系问数、物流运单数 800，并确认其他服务未变化。失败即阻止部署或回滚。

## 后续阶段

- P1：针对字段展示、程序解释、质检分别试验模型角色参数（小样本已提示非思考模式有潜力，尚不能替代完整 E2E）。
- P1：为结果字段增加可信的类型与聚合来源，再做无模型展示路径；现有 outKeyRefs 无法区分 count/sum/比例以及 Python 二次变换，不能凭列名猜测。
- P2：结构化查询、已验证计划复用及本体版本关联的缓存，先建立正确性与失效测试再上线。

本轮不需要 ONN Core 新功能。后续若缺少查询耗时、计划或版本信息，单独提出接口需求，不修改其代码或部署。
