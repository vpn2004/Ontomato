## 本轮发现的问题与安排

### 1. 两套环境未配置 embedding 模型

业务配置中 embedding 的 base URL、模型名与 API key 均为空；向量检索来源中的模型配置也为空。运行日志出现 `Vector query error: baseUrl cannot be null or blank`。当前知识检索路径捕获异常后按空知识继续运行，因此结构化问数仍成功。

影响：不能据本轮结果认定知识库、附件、文档向量检索可用；还会增加无效调用和错误日志。

安排：配置真实可用的 embedding endpoint、模型和凭据，按既有向量表的维度校验，再单独验收检索及文档问题。不能直接套用聊天模型配置，也不能随意改变已有向量维度。本轮未修改模型配置。

### 2. 模型规划会生成 adapter 不支持的 DSL

日志中出现行级 `DISTINCT` 被拒绝，以及多步骤/临时结果 DSL 被拒绝（`exactly one steps`）。关系问题尤其有多次重试，最终使用应用侧处理等方式得到正确答案。物流问题另有一次工具文件路径限制报错，模型随后恢复。

影响：答对不代表执行路径已经高效，实际关系问数约 125 秒；不能把这些重试时间归因于 ONN Core 的图查询耗时或磁盘整理。

安排：优先让规划器明确识别当前 adapter 的单步骤、去重和后计算能力，减少反复尝试不支持的 DSL；再按既有 DSL 语义设计行级去重和多步骤组合的实现及边界测试。扩大支持前需分别验证重复路径、空值、排序、分页、计数和来源窗口，不能通过静默忽略操作来提速。这属于 Ontomato 的 adapter/规划协作事项；本轮没有发现需要 ONN 团队紧急升级 108 才能解除的查询阻断。

### 3. 剩余验收边界

本轮未执行 Action 或其他业务写入，未进行持续压测、备份恢复、故障注入、大数据量和新一轮 ONN/PG 对照。前轮 Manager 后端探索已通过，此轮没有增加 Manager 图交互的完整浏览器验收。后续应按对应场景独立验收，不能以本轮只读通过替代。
