# ONN Core V12.4 综合验收与下一迭代交付要求

验收日期：2026-10-23  
验收对象：ONN Core `066aedb2`（V12.4 引擎实现 `04afc710`）及 192.168.1.108 上已部署的隔离实例  
用途：第三方客户端通过 HTTP 使用 ONN Core 管理和查询业务对象、关系与指标。

## 结论

V12.4 关闭了 V12.3 已登记的类身份冲突、空窗口总数和 Pipeline 空集指标问题；这些旧问题不应继续描述为“修复不完善”。扩大组合覆盖后，本轮发现查询分页、治理过滤、分组分页、投影裁剪和请求校验问题；边界补测进一步确认了资源授权绕过、继承属性泄露、冒号 ID 截断及读取故障被转换为无数据的问题。108 上另行复现了时间窗口分页和向量候选计数问题。

当前版本**不能作为通过安全与正确性验收的接入基线**。建议 ONN Core 下一迭代集中修复本报告 P0/P1 项，并在同一迭代交付自动化回归和隔离部署验收。完成之前，只使用合成数据做隔离联调，不接入真实敏感业务数据。

本轮没有修改 `/Users/weichen/Documents/dev/onn-core` 中任何文件，也没有在 108 上写入 fixture。源仓库本地 `go test` 的 domain/API 定向套件及 race 定向套件通过。独立消费者 HTTP 矩阵执行 159 个请求，其中 104 个符合断言、55 个未符合；这 55 个按共同根因合并如下，不应当作 55 个独立缺陷。完整测试源和脱敏逐请求记录见 [验收包](acceptance/onn-core-v12.4-comprehensive/README.md)。

补充边界检查共 14 条，2 条符合预期、12 条未符合，包含 4 条 KV 故障注入检查。2026-10-23 通过交付脚本复跑，结果一致。本报告合并为 **10 项独立修复要求：P0 5 项、P1 5 项**；尚未交付或未验收的能力另列，不包含在这 10 项中。

## 已确认问题与交付要求

### P0：查询失败和非法 DSL 必须显式失败

矩阵中负 `offset` 会导致 HTTP 500；负 `limit`、负 `branch_limit`、未知 `count_mode`、非法逻辑操作符、`in` 值类型错误、负 `top_k`、超范围 `score_threshold`、缺失/空/重复 metric 名称及非法 `relative_time` 未按客户端错误拒绝。部分条件静默不执行或出现不稳定的执行错误。

**要求：** 对所有入口（Native、Pipeline root、Pipeline `from_step`）统一做结构、类型、范围、枚举、引用及组合校验。无效请求返回稳定 4xx 错误码和字段路径；不能 panic、返回 500、静默忽略条件，或将存储/执行错误包装成空结果。为阈值范围、负值边界和可选字段语义补充版本化契约，避免客户端猜测。

**验收：** 验收包中所有无效请求均返回 4xx，合法边界值成功；同一请求在三种执行路径上错误类别一致。故障注入覆盖 KV Scan/Get 错误，必须返回可识别服务错误，不能报告 `exact 0`。

### P0：时间窗口过滤必须先于分页并保持总数可信

159 请求矩阵确认 Native、Pipeline 及 `from_step` 的窗口分页结果不稳定：窗口内数据若不在候选首行可能被漏掉；`total_matched`、`has_more` 与实际匹配集合不符；`from_step` 窗口过滤行为未正确执行。108 上的独立 fixture 复现了 Native/Pipeline `limit=1` 返回窗口总数 1、`has_more=false`，但完整匹配集有 2 条；仅包含后续候选的窗口会错误返回空集。

**要求：** 在完整的候选集合上执行窗口过滤，再计算过滤后总数和分页；若因扫描上限无法得到精确总数，应明确返回 unknown/nullable total 与截断原因。Native、Pipeline 与 `from_step` 必须保持相同语义。

**验收：** 覆盖窗口内多行、首候选不匹配但后续候选匹配、offset 翻页、无匹配窗口、窗口边界、limit 大于/小于匹配数；结果集合、总数、`has_more` 与全量基准一致。无法精确计算时不得返回 `count_kind=exact`。

### P1：治理 record_filter 必须准确影响结果、计数和分页

矩阵中 Native/Pipeline 的 `governance.record_filter` 结果集合及 count 不一致；Pipeline `from_step` 虽过滤了记录，返回总数仍按过滤前集合计算。治理规则不能只应用于响应数据而跳过完整性统计。

**要求：** record filter 在分页和所有统计之前生效；完整性字段基于治理后集合。规则解析失败不得被忽略或退化为无治理查询。

**验收：** 三种路径对相同过滤条件返回相同集合、精确总数和翻页状态；加入分页、聚合和空集用例；无权/无效规则按明确定义拒绝。

### P1：分组结果分页与计数必须按组计算

`group_by + limit=1` 的矩阵断言未通过：当前页一组时，返回的 `total_matched`/`has_more` 没有表达完整分组数，三种执行路径表现应统一。

**要求：** 明确分组结果的 `page_count`、`total_matched` 和 `has_more` 表示组还是源对象；同一查询的 count、having、order_by 与分页顺序应稳定。建议分页在分组、指标、having 后进行。

**验收：** 至少 3 个组，分别用 limit=1、offset、having、排序和空组输入；各页拼接等于完整组集合，计数类别明确，Native/Pipeline 语义一致。

### P1：投影必须裁剪原始对象属性

选择 `name AS age` 的投影用例仍在 `data[].attributes` 中带有未选择的原始 `age`，导致响应既违反字段选择语义，也可能让调用方误读别名。当前证据证明的是投影裁剪缺陷，**不据此声称已经发生敏感字段越权**；权限旁路需单独的安全测试。

**要求：** 所有响应区域一致遵守输出字段选择；投影别名不得覆盖或混淆源属性名。若提供原始对象，应通过显式字段或模式选择，不得在投影模式下隐式返回全部业务属性。权限过滤仍须独立于投影执行。

**验收：** 选择一个字段、别名与现有属性同名、多个别名、投影加指标、受限字段和关联对象；检查 `data`、`projected`、`metrics` 及错误信息均不包含未授权/未选择属性。

### P1：向量重排的 source_candidate_count 不得被 top_k 覆盖

108 上 3 个源候选、`top_k=2` 时，`total_matched=3` 正确，但 `source_candidate_count=2`。它被重排后的输出数量覆盖，不再表示进入向量排序的源候选规模。

**要求：** 固定字段定义并保存过滤后、重排前的候选数量；如还需表达有效向量数或阈值后数量，应使用独立字段。不得以 top_k 页面大小替代源候选数。

**验收：** 有缺失向量、阈值过滤、top_k 截断与排序并列的 fixture；各计数字段按文档定义逐项核对。

### P0：资源级授权必须覆盖查询实际访问的所有类和关系

新增内存 fixture 注入按 `AuthorizationResource.ClassPath` 拒绝 `/review/secret` 的 Authorizer。直接查询 secret 类正确返回 403，但以下三种请求均返回 200，并实际读取 secret 类对象：Pipeline 第二个独立 step、从 public 类遍历到 secret 类、仅声明 secret 类的 vector query。属性级过滤不是资源授权替代品；遍历响应还直接包含目标类属性。

**要求：** 在解析出完整执行计划后，对所有实际扫描、遍历、向量读取和 pipeline step 的类/关系逐项授权，再执行任何读取。类冲突或无法确定资源身份时 fail closed。授权范围与执行器最后实际访问的资源必须一致。

**验收：** 允许/拒绝 Authorizer 覆盖 direct、pipeline 每个 step、至少两层遍历、目标 relation、vector-only 和 from_step。任一目标类被拒绝时整个请求 403，不能先返回部分结果或读取目标属性；允许场景继续成功。

### P0：子类读取必须继承父类属性安全策略

新增父类 `/review/parent`，其 `salary` 标记为 restricted 且仅 `hr_admin` 可读；子类 `/review/child` 声明 `ParentPath` 并存有该字段。`reader` 对实例 GET 收到 HTTP 200，`attributes.salary=50000`；`hr_admin` 正常读取。该结果确认继承属性定义没有进入子类的安全过滤表。

**要求：** Schema 继承后的有效属性及其安全策略必须统一用于查询授权、响应清理、实例读取、投影、过滤、排序、指标与关系读取。父类定义冲突需有确定的 schema 校验规则。

**验收：** reader 在所有入口无法读取、推断或筛选受限父类字段；`hr_admin` 可读取；父类策略读取失败或继承链循环时 fail closed。

### P1：对象和边身份编码必须可逆，分隔符不能造成静默数据丢失

新增内存 fixture 以 `item:a` 为实例 ID 写入 `name=first`。`GetInstance` 返回成功但属性为空，`ScanClassInstanceIDs` 不返回该对象。边 `from:a -> to:b` 的出/入邻居分别被解析为 `b` 和 `a`。这是可复现的身份截断和静默漏数，不只是源码格式风险。

**要求：** 对 class path、instance ID、relation path 和属性名使用可逆编码或长度前缀格式；迁移期间兼容已有 key。若输入暂不支持，写入时必须明确拒绝。所有扫描、去重、索引、边查询与删除使用相同的结构化身份解析。

**验收：** 含冒号、Unicode、空格及编码边界的实例/边可完整写入、读取、扫描、查询和删除；不得以成功空对象或截断 neighbor 表示成功。

### P0：存储故障必须传播为服务错误，不能伪装成无数据

使用嵌入真实 KVStore 的 wrapper，仅在数据键 Get、ScanPrefix 或 ScanKeysOnly 上注入 `synthetic storage unavailable`：

| 路径 | 结果 |
| --- | --- |
| GetInstanceProjection 的属性 Get 失败 | 返回 `(nil, nil)`，读取失败变为无对象 |
| HTTP 实例 GET 的 ScanPrefix 失败 | 404 `INSTANCE_NOT_FOUND`，错误地声称对象不存在 |
| Native 查询水化 ScanPrefix 失败 | 200，空 data，但 `total_matched=1`、`count_kind=exact` |
| Native 查询候选 ScanKeysOnly 失败 | 200，`count_kind=exact`、`total_matched=0`，伪造精确空集 |

**要求：** 区分 key not found、值损坏、存储不可用、取消与超时。非 not-found 错误必须向上传播；水化/候选扫描失败不得被忽略。若产品允许部分结果，必须采用显式请求模式并返回非完整性状态，不能作为普通成功结果。

**验收：** Get/Scan/解析失败注入覆盖实例、投影、列表、聚合、pipeline、图邻居和缓存 miss；返回稳定 5xx/明确降级状态，绝不返回假 404 或 exact 空集。健康状态的真正空集和字段 missing 继续符合原契约。

## 原需求对账与未覆盖能力

V11 指南及早期功能需求 R01-R10 里的服务版本/能力契约、严格 DSL、完整性、稳定分页和快照、多分支/Pipeline、跨对象绑定、完整邻居边列表、聚合/投影、安全、Schema 校验和编辑状态声明，应逐条维护交付矩阵。本轮新发现只覆盖运行时组合行为，不等同于这些需求全部验收。

尤其以下能力仍为独立未交付/未验收项，不要用本报告的新缺陷替代其排期：稳定 cursor 与一致快照、完整跨对象绑定结果、完整邻居/边分页 API、生产认证/TLS/凭证轮换、持久化向量索引、编辑合并/历史端点实际启用状态。若下一迭代目标只是“受控 adapter 可用”，团队应在能力发现接口中明确未启用项和限制；若目标是完整业务图能力，则需分别纳入验收范围。
