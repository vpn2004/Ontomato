## 必须集中补齐的实现

### 1. Q01/Q03/Q04/Q05：24 条原有 HTTP 失败仍未解决

无需新增需求即可复现：原消费者矩阵原样运行仍有 24 条失败，即校验 15 条、治理 3 条、分组 3 条、投影 3 条。

请按计划统一执行顺序与字段来源，不仅修改总数或测试预期。`trimInstanceAttributesToOutput` 仍将源字段名和别名都加入保留表；分组调用方仍拿分页后组数填 total；治理过滤后仍回用过滤前 total。这些都是已登记的问题，不应再次标记阶段完成。

### 2. S01：关系资源未授权

注入只拒绝 `/review/link` 的 Authorizer，允许两端类。Native 与 Pipeline 都返回 200，Native 返回目标对象属性。`handlers.go` 的两个资源授权循环直接跳过 `r.Kind != "class"`，未向策略提交 `RelationPath`。

要求：使用明确的关系读取授权动作和资源身份，不能把“允许目标类”当作“允许关系”。补两层、多分支、from_step 和允许/拒绝矩阵，观察实际业务读取，不只测试资源枚举函数。

### 3. S02：同名继承字段的两条实际泄漏

- 父 `salary=public`、子 `salary=restricted`：reader GET 返回 `attributes.salary=50000`，同时 attribute_states 却标 unreadable。
- 父 restricted、子 public：reader 对子类执行 sum(salary) 返回 200，`metrics.s=50000`；实例属性虽被删除，聚合值仍泄露。

原因：有效定义简单按子→父追加，响应字典由后出现的父定义覆盖，而引用授权查找第一个子定义。两条路径没有同一份有效安全策略。

要求：绑定时合并有效策略，禁止隐式放宽，允许收紧时采用约束交集；同名类型冲突明确拒绝。所有过滤、排序、聚合、投影、响应和缓存使用同一结果。不能靠最后清空 attributes 掩盖指标泄漏。

### 4. D01：混合版本兼容未完成

- 同一 relation 下有旧边和新边：`GetOutboundNeighborsBatch` 只返回新边，因为仅在 V2 集合为空时回退旧前缀。
- `RemoveEdge` 对旧边返回成功，随后仍能查询到旧边；删除只处理 V2 key。
- 同对象旧值 OLD 与新值 NEW 共存：`GetInstance` 多次读到旧值。逐键字符串去重无法合并两个不同编码指向的同一属性；map 遍历顺序影响覆盖。应以结构化身份去重，V2 明确优先。

以上已在计划 4.6 的双读、去重、更新/删除与防旧值复活要求内。迁移 dry-run、冲突报告、中断恢复、备份/回滚材料在交付中也未给出完整证据。

### 5. D01 长 ID：空前缀造成跨对象读取和删除（P0）

在独立内存 KV 中仅创建 `/review/unrelated/other`，属性为 `private=UNRELATED`。对另一类 `/review/long`、600 字节且不存在的 ID 调用仓储层：

- GetInstance 成功返回 unrelated 对象的属性，却挂在请求的类和 ID 下。
- DeleteInstance 成功后，原 unrelated 对象变成 not-found。

原因：`BuildInstancePrefixV2` 超过固定 512 字节返回 nil，仓储未判空，把 nil 作为无范围限制的扫描前缀。codec Safe builder 支持长字符串不代表全链路已接线；普通 SaveInstance 的长 ID 写入另会报 `Key cannot be empty`。

要求：所有长度检查在扫描/删除前完成，非法输入不得变成空前缀；统一安全构造器及错误通道，并校验解析后的真实对象身份。新增不存在长 ID、长类路径、长 relation 的隔离测试和 HTTP 入口验证。

**本轮只在合成内存 fixture 执行了上述删除，没有操作任何持久化数据库或服务器；目前证实的是仓储层隔离破坏，不将它冒称为已在 108 复现的 HTTP 漏洞。**

### 6. D02：查询和双读路径仍吞错

- 候选 ScanKeysOnly 失败：HTTP 200、total=0、count_kind=exact。
- 水化 ScanPrefix 失败：HTTP 200、空 data、total=1、count_kind=exact。
- V2 属性 Get 故障且存在旧副本：投影读取用旧数据覆盖真实错误，成功返回 LEGACY。
- 旧格式 ScanPrefix 故障：GetInstance 忽略故障并返回普通成功。

要求：仅 not-found 可触发读回退，`val==nil` 不能覆盖其他错误。双读任一必要扫描失败都传播服务错误。executor 条件、水化、候选辅助函数需要 error 通道；外层 timeout/circuit-breaker 自动 200 降级仍须按原计划审计，不能只修 GET 的返回码。

### 7. S5/S0 契约：Native 路径尚未接通

相似度约为 1、0.707、0 的三个对象，`score_threshold=0.9`：Native 和 Pipeline root 均返回 3 条，from_step 正确返回 1 条。Native 构建 VectorSearchRequest 时没有传阈值；只改 rerank 无法覆盖全部入口。

Native 普通查询响应也缺少已承诺“始终返回”的 `pageable_count`，因为手工 gin.H 没有接新字段。Native 向量 source_candidate_count 仍为 0。请统一三路径的公开 DTO、计数来源与序列化；阈值要覆盖省略、显式 0、负值、正值及 top_k/排序组合。

## 交付证据仍有缺口

1. **未运行原消费者包作为关闭门槛。** 新增 TestV125* 通过与原 159 请求失败可以同时发生，不能以仓内全绿替代对账。
2. **S2 socket 脚本未测试资源拒绝。** 脚本注释明确无 authorizer，只断言合法遍历 200，不证明拒绝路径通过。
3. **S3 socket 脚本未注入存储故障。** 仅检查存在 200、不存在 404、真空集 200，不能关闭 D02。
4. **S7 尚未完成 108 隔离验收。** 本地 18257 冒号 ID 冒烟不等于计划规定的 108 新目录、新后端和网关端口部署。无需现在带着红灯部署；修完后集中执行。
5. **race 未通过。** 原共享 AST 问题可作为既有债单列，但不得写成 race 通过。本轮计划明确要求运行时状态与 AST 分离和并发复用不污染，延期需明确缩小支持范围并证明调用边界隔离，不能仅以存量为由宣布安全。
6. 缺最终版本化契约、10 项需求-测试-提交-证据完整矩阵及隔离发布 manifest，S0 草案不能替代 S7 定稿。

## 对 S0 四个应用层问题的反馈

1. 当前 adapter 仅支持受限单类读取，不依赖多分支截断成功；保持默认失败，不为应用层自动设置 opt-in。
2. 接受 `pageable_count`、`count_scope` 的方向，但需全部公开入口一致，准确区分候选、匹配总数、可分页窗口及上游输入范围。S0 示例把 total_matched 称“源候选数”而 source_candidate_count 又为 4，应修正文案。
3. 请求可修正的语义/结果预算契约错误建议 422 + 稳定 code/path；真实存储错误按 5xx、超时按明确超时错误，不依赖文本猜测。
4. 不需要把默认失败静默切回成功的灰度开关。若其他客户端确需兼容，单独声明版本/能力和退出条件，不改变本 adapter 的严格失败要求。
