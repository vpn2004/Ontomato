# DSL 重试保护：优化前后对照验收

日期：2026-11-13。验证对象：`74e9a047` 的谓词前置校验、关系错误提示与 ONN DSL 连续失败预算。

**结论：防错机制通过验证；本轮观察到答案更早完成，但整轮等待没有改善，整体性能优化尚不能判为通过。** 新旧版各测试三次同一道跨关系问题，业务结果全部正确。答案时间中位数从 54.90 秒降至 46.31 秒，缩短约 15.6%；整轮结束时间中位数从 103.38 秒变为 105.34 秒。新版两次自动质检超时，需要继续处理应用层等待。

## 哪些机制已经生效

真实网页三轮新版都出现了一次数组形式的 `conditions.properties`。前置校验均明确返回错误位置，模型下一次 DSL 试跑成功。新版三次前置拒绝都没有产生查询分发事件；不能仅统计 `m3.query.failed` 就得出“新版没有语法错误”。这些历史事件名同样用于 ONN 工具分发，不表示启用了 M3 模式。

新版第 1 轮还发生了一次 `ambiguous or unknown binding variable`，随后修正成功。该轮两次失败之间有成功查询，日志两次都显示 `1/4 consecutive`，与成功清零的规则一致。新版仍会首次生成错误，前置校验主要改善定位与拒绝行为。

补充了 6 项自动化用例，并运行相关定向回归，共 **41 项通过，0 失败、0 跳过**：

| 测试类 | 数量 | 验证内容 |
|---|---:|---|
| `DslSkillToolsFailureBudgetTest` | 5 | 实际文件入口和 dispatcher 路径；4 次非法谓词后合法的第 5 次也被拒绝；失败记录保存；成功清零和新调用重置；adapter 异常消耗预算；未启用预算的 adapter 行为不变 |
| `AgentCallContextTest` | 2 | 预算作用域；16 个线程争抢同一个调用上下文时仅 4 个获得预留，结束后 pending 为 0、失败为 4 |
| `DslGrammarValidatorTest` | 9 | 谓词结构、嵌套错误路径、合法逻辑条件及已有 timeseries 规则 |
| `OnnCoreGraphCompilerTest` | 6 | 关系方向及候选提示、图语义和不支持形状的明确拒绝 |
| `OnnCoreDslCompilerTest` | 19 | 已有 DSL 编译、去重及相关语义回归 |

新增入口用例使用可计数 mock adapter，不连接外部数据库或模型；验证的是保护机制和调用次数，实际数据正确性由六轮网页对照提供证据。真实网页本轮没有自然触发连续 4 次失败，不能把入口测试表述为线上模型已触发预算耗尽。

复测命令，在正确的工作树及项目要求的 Java 环境执行：

```sh
./mvnw -pl packages/data-engine-core,packages/data-adapters/onn-core -am \
  -Dtest=DslSkillToolsFailureBudgetTest,AgentCallContextTest,DslGrammarValidatorTest,OnnCoreGraphCompilerTest,OnnCoreDslCompilerTest \
  -Dsurefire.failIfNoSpecifiedTests=false test
```

预算的边界需要保留：它限制单次 Agent 调用中经过 `DslSkillTools` 的连续失败尝试，成功后清零，新 Agent 调用重新计数。它不是整个聊天最多查询 4 次，也不是模型总轮次或总时长上限。文件路径/JSON 解析在此预算入口之前，后续 Python 程序直接调用执行 API 也不受同一个工具预算计数；不能承诺它终止所有形式的循环。

## 后续建议及验收门槛

1. **优先改进质检生命周期与呈现。** 将答案可用和质检完成明确区分；质检独立跟踪、可恢复并持久化完成/失败/超时状态，刷新后也能获知真实状态。设计时保留证据及取消语义，不以隐藏质检或单纯缩短超时冒充提速。
2. **降低首次错误和重复代码生成。** 为当前 schema 提供可校验的谓词、变量和有向关系示例，复用已验证 DSL 生成执行代码。重点处理本轮仍重复出现的数组谓词与变量绑定错误；继续保留失败预算。
3. **单独优化质检模型链路。** 小规模比较精简程序说明、在有界并发下解释独立子程序等方案，检查评审质量及模型限流。不能根据本轮证据承诺改动后的耗时。

后续仍用相同问题和逐项基准对照，并增加单表筛选、聚合、空结果及复杂关系题。分别报告首次生成成功率、答案时间、整轮结束时间和质检完成率；本题至少应消除本轮出现的质检超时后，再讨论扩大部署。不要把没有输出质检结果的轮次计为完整通过。
